> **Objetivo / Goal:** De 0 a proyecto corriendo en la primera semana, con toda la documentación, accesos y expectativas alineadas. / *From 0 to a running project in the first week, with all documentation, access, and expectations aligned.*

---

## Inglés / English

### Phase 0 — Before Kickoff (Sales → Delivery handoff)
- [ ] SOW & MSA signed, deposit received
- [ ] Sales handoff call between Account Manager and Delivery Lead
- [ ] Project created in Jira (`[CLIENT]-project`)
- [ ] Confluence space created for the client (or shared space)
- [ ] Client added to Slack channel `#client-[name]` / `#proyecto-[name]`

### Phase 1 — Kickoff Week
- [ ] Kickoff meeting scheduled (attendees: client stakeholders + tria team)
- [ ] Introduction deck shared (team, process, communication plan, tools)
- [ ] Communication plan confirmed: status reports cadence, POC list
- [ ] Tool access granted:
  - [ ] Jira / project board (client-view or full)
  - [ ] Figma (design files)
  - [ ] Dev/Staging environments (as agreed)
  - [ ] Repositories (as agreed)
- [ ] Requirements & acceptance criteria baseline captured in Jira
- [ ] First sprint planned (or roadmap presented for project-based)
- [ ] Definition of Done agreed
- [ ] Billing / invoicing contact confirmed (accounts@ email, billing data)

### Phase 2 — First Sprint / First Delivery
- [ ] Environment setup completed (staging URL shared)
- [ ] CI/CD pipeline visible (commits → deploy)
- [ ] Weekly status report template in place
- [ ] Client demo cadence confirmed (end-of-sprint demo)
- [ ] Feedback channel confirmed (Jira comments vs. Slack)

### Phase 3 — Steady State
- [ ] Change request process documented
- [ ] Escalation path documented (tria POC → CEO if needed)
- [ ] Quarterly business review (QBR) scheduled

### Project Handover Checklist (on completion)
- [ ] Full source code delivered (repo access or transfer)
- [ ] Technical documentation (README, architecture, runbook)
- [ ] API documentation (Swagger/Postman)
- [ ] Admin/user guides
- [ ] Credentials & secrets handed over securely (password manager)
- [ ] Domain, DNS, hosting access transferred (as agreed)
- [ ] Post-launch support period defined
- [ ] Final invoice & acceptance signed

## Español / Spanish

### Fase 0 — Antes del Kickoff (Handoff Ventas → Entrega)
- [ ] SOW y MSA firmados, anticipo recibido
- [ ] Llamada de handoff entre Account Manager y Líder de Entrega
- [ ] Proyecto creado en Jira (`[CLIENTE]-proyecto`)
- [ ] Espacio creado en Confluence para el cliente (o espacio compartido)
- [ ] Cliente agregado al canal de Slack `#cliente-[nombre]` / `#proyecto-[nombre]`

### Fase 1 — Semana de Kickoff
- [ ] Reunión de kickoff agendada (stakeholders del cliente + equipo tria)
- [ ] Deck de presentación compartido (equipo, proceso, plan de comunicación, herramientas)
- [ ] Plan de comunicación confirmado: cadencia de reportes de estado, lista de POCs
- [ ] Accesos otorgados:
  - [ ] Jira / tablero del proyecto (vista cliente o completa)
  - [ ] Figma (archivos de diseño)
  - [ ] Ambientes dev/staging (según acuerdo)
  - [ ] Repositorios (según acuerdo)
- [ ] Requisitos y criterios de aceptación base capturados en Jira
- [ ] Primer sprint planificado (o roadmap presentado para proyectos fijos)
- [ ] Definición de Hecho (Definition of Done) acordada
- [ ] Contacto de facturación confirmado (correo de cuentas, datos de factura)

### Fase 2 — Primer Sprint / Primera Entrega
- [ ] Setup de ambientes completado (URL de staging compartida)
- [ ] Pipeline CI/CD visible (commits → deploy)
- [ ] Plantilla de reporte de estado semanal lista
- [ ] Cadencia de demo confirmada (demo al final del sprint)
- [ ] Canal de feedback confirmado (comentarios en Jira vs. Slack)

### Fase 3 — Estado Estable
- [ ] Proceso de change requests documentado
- [ ] Ruta de escalamiento documentada (POC tria → CEO si es necesario)
- [ ] Revisión trimestral de negocio (QBR) agendada

### Checklist de Entrega del Proyecto (al completar)
- [ ] Código fuente completo entregado (acceso o transferencia de repo)
- [ ] Documentación técnica (README, arquitectura, runbook)
- [ ] Documentación de APIs (Swagger/Postman)
- [ ] Guías de administración y usuario
- [ ] Credenciales y secretos entregados de forma segura (password manager)
- [ ] Acceso a dominio, DNS y hosting transferido (según acuerdo)
- [ ] Período de soporte post-lanzamiento definido
- [ ] Factura final y aceptación firmada
